# Онлайн-деканат

Цифровой секретарь для студента: читает фото/скан студенческого документа, раскладывает данные по полям,
выполняет предварительную проверку комплектности по Положению и отвечает на вопрос на русском языке
со ссылками на поля документа и пункты Положения. Если ответа нет в документе и Положении — честно говорит об этом.

Кейс хакатона «Онлайн-деканат» (ЦентрИнвест). Все документы и правила — учебные.

**Интерфейсы:** веб-приложение (Django + React) и Telegram-бот (транспорт к тому же API).
**Без внешних API:** OCR и ответы формируются локально на CPU; языковые модели не используются — ответы детерминированные.

## Результаты

| Набор | Точность полей | Предварительная проверка | Вопросы (answerable/value/sources) |
|---|---|---|---|
| Открытый набор, 30 PNG (`data/documents/*.png`) | **1.000** | **1.000** | **1.000** |
| Открытый набор, 30 PDF (рендер страницы) | **1.000** | **1.000** | **1.000** |
| Синтетический набор, 15 документов с новыми ФИО/вузами/датами (`scripts/synth_generate.py --seed 11`) | **1.000** | **1.000** | **1.000** |

Автоопределение типа документа: 30/30 на открытом наборе. Подпись/печать: 60/60 отметок.
Устойчивость к плохим снимкам: наклон 5/15/30°, перспектива, тень, блик, шум, размытие — 1.0 по всем метрикам; таблица в разделе «Бонусы».

## Быстрый старт

Требования: Python 3.10–3.12 (PaddlePaddle пока не поддерживает 3.13+), Node.js 18+ (для фронтенда),
Tesseract 5 (резервный OCR; необязателен, но рекомендуется).

```bash
# 1. окружение
py -3.12 -m venv .venv            # Linux/macOS: python3.12 -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements/dev.txt

# 2. модели (PaddleOCR скачивается автоматически; Tesseract rus/eng -> models/tessdata)
python scripts/download_models.py

# 3. проверка на открытом наборе -> results.json + метрики evaluate.py
python scripts/predict.py --manifest data/documents.json --questions data/questions.json --base data \
    --input image --out results.json --reference data/reference_results.json

# 4. веб-приложение: сборка фронтенда и запуск Django (один порт :8000)
cd frontend && npm install && npm run build && cd ..
cd backend && python manage.py migrate && python manage.py runserver 0.0.0.0:8000
# открыть http://localhost:8000  (Swagger: http://localhost:8000/api/docs/)

# 5. Telegram-бот (в другом терминале)
set BOT_TOKEN=...   # export BOT_TOKEN=... ; API_BASE_URL=http://localhost:8000 по умолчанию
python -m bot
```

Windows PowerShell: `.\tasks.ps1 venv|models|predict|build-frontend|serve|bot`. Make: `make venv models predict backend bot`.

## Закрытый набор (сдача results.json)

```bash
python scripts/predict.py --manifest data/closed/documents.json --questions data/closed/questions.json \
    --base data/closed --input image --out results.json
# формат проверяется схемой results.schema.json; для самопроверки формата:
python data/evaluate.py --reference results.json --predictions results.json
```

Тип документа берётся из манифеста (`document_type`); флаг `--auto-type` принудительно включает автоопределение.
Ошибка на одном документе не прерывает прогон: такой документ получает «не найдено»/`false` по всем полям и попадает в лог.

## Как это работает

```
файл (JPG/PNG/PDF) ─► предобработка ─► OCR ─► строки «Метка: значение» ─► поля (конфиг типа) ─► подпись/печать
                      поворот 90/180°,  PaddleOCR      склейка боксов       нормализация дат,     цвет/форма,
                      наклон ≤30°,      + Tesseract    в строки             ФИО, номеров,         якоря «Подпись:»
                      тени, блики,      (резерв)                            «не найдено»          и «М.П.»
                      апскейл
                                                                 ▼
                           ответ ◄── интенты (без LLM) ◄── проверка по Положению (rules.md)
                     value + sources      decision / completeness / field /       status, missing_fields,
                     + текст              faq / not_established / no_info         sources = rule:X.Y
```

1. **Загрузка** (`core/dekanat_core/io`): JPG/PNG через Pillow (учёт EXIF-поворота), PDF через PyMuPDF (рендер 200 dpi; поддерживается одна страница).
2. **Предобработка** (`preprocess/`): ориентация страницы 90/180/270° (классификатор PaddleX `PP-LCNet_x1_0_doc_ori`, резерв Tesseract OSD); оценка качества снимка; для фото — поиск контура листа и выравнивание перспективы, удаление теней и бликов, коррекция наклона по Hough-линиям (до ±30°), апскейл мелкого текста. Матрица преобразования сохраняется, чтобы показывать подсветку и на исходном снимке.
3. **OCR** (`ocr/`): PaddleOCR PP-OCRv5 (`PP-OCRv5_mobile_det` + кириллическая `eslav_PP-OCRv5_mobile_rec`), модели paddlex вызываются напрямую с батчингом строк. Tesseract 5 (`rus+eng`) подключается, если у основного движка низкая уверенность или не найдены метки полей; результаты объединяются по IoU.
4. **Поля** (`extract/`): конфиг типа (`config/doc_types/*.yaml`) задаёт метки, синонимы, тип значения и пункт Положения. Метка ищется нечётко (rapidfuzz, устойчиво к OCR-ошибкам и латинским гомоглифам вроде «Kypc»), значение — после двоеточия. Пустые значения/подчёркивания → `не найдено` (п. 2.2 — без домыслов). Нормализация: даты `01.09.2023` и `1 сентября 2023 года` → `2023-09-01`; курс → целое; ФИО/номера/группы — гомоглифы в кириллицу; кавычки → «ёлочки».
5. **Подпись и печать** (`marks/`): по якорям «Подпись …:» и «М.П.» определяется зона; подпись — связная «чернильная» компонента заметной ширины/высоты после удаления линии; печать — синяя окружность (Hough) или компактное синее пятно. Надписи сами по себе отметкой не считаются (п. 2.3).
6. **Проверка** (`rules/validator.py`): `missing_fields` — пустые текстовые поля и отсутствующие отметки; `sources` — пункты, установившие недостающие элементы, либо все пункты типа для полного документа (п. 6.1/6.2).
7. **Ответы** (`qa/`): детерминированный разбор вопроса — «кто принимает решение» (п. 1.3), комплектность (в т.ч. «хватит ли для перевода» — с оговоркой п. 3.5), значение поля (кавычки или синонимы из конфига; темы вроде стипендии/телефона/стоимости блокируют случайные совпадения), FAQ по явным пунктам Положения (подлинность — 2.3, формат дат — 2.5, печать на заявлении — 4.3 …), «не установлено Положением» (3.5/4.4/5.5) и отказ по умолчанию (п. 6.3). Инвариант: `sources` пусты ⇔ `answerable=false`; `value` и `answer` формируются одной функцией и не противоречат друг другу.

## Структура репозитория

```
config/doc_types/*.yaml      типы документов (поля, синонимы, пункты Положения) — новый тип без кода
config/intents.yaml          словари интентов и FAQ по Положению
config/settings.yaml         пороги OCR/детекции, пути
core/dekanat_core/           ядро (без Django): io, preprocess, ocr, layout, extract, marks, rules, qa, pipeline
backend/                     Django 5 + DRF: API, хранение результатов, выдача картинок, Swagger
frontend/                    React 18 + Vite + TypeScript + Tailwind
bot/                         aiogram 3, long polling, только транспорт к API
scripts/predict.py           манифест + вопросы -> results.json (+ evaluate.py)
scripts/robustness_bench.py  бенчмарк «плохих снимков»
scripts/synth_generate.py    синтетические документы с новыми значениями
scripts/download_models.py   предзагрузка весов
tests/                       pytest: нормализация, валидатор, интенты (100+ кейсов), e2e (-m slow)
data/                        стартовый пакет организаторов (rules.md, документы, эталон, evaluate.py)
```

## API (Django REST, `/api/v1`)

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/doc-types` | типы документов из конфигов (ключ, название, поля) |
| GET | `/rules` | Положение по разделам и пунктам |
| POST | `/documents` | multipart `file`, `doc_type` (`auto`/ключ), `question` или `check=true` → карточка + ответ; с `async=1` отвечает сразу `202` (`status=processing`), результат и ответ на вопрос появляются в `GET /documents/{id}` — так работают веб и бот, чтобы медленные каналы/туннели не обрывали запрос |
| GET | `/documents/{id}` | результат: поля с bbox, проверка, OCR-текст, история вопросов |
| POST | `/documents/{id}/ask` | `{question}` → ответ (без повторного OCR) |
| POST | `/documents/{id}/check` | самопроверка — стандартный вопрос о комплектности (п. 6.5) |
| PATCH | `/documents/{id}` | `{doc_type}` — сменить тип вручную (переизвлечение по готовому OCR) |
| GET | `/documents/{id}/image?variant=original\|normalized` | изображения |
| GET | `/documents/{id}/annotated.png`, `/fields/{key}/crop.png` | снимок с рамками / фрагмент поля |
| GET | `/documents/{id}/export.json` | документ в формате `results.json` |
| GET | `/health`, `/api/docs/` | состояние движков, Swagger UI |

## Веб-интерфейс

- Загрузка перетаскиванием, выбор файла или съёмка камерой на телефоне; тип — «автоматически» или вручную.
- Вопрос с подсказками или кнопка **«Проверить без вопроса»**.
- Страница документа: снимок (выровненный/исходный, зум) с рамками полей — зелёные найдены, красные «не найдено», синие подпись/печать; клик по полю, по источнику `field:*` или по пропуску в проверке подсвечивает место на снимке. Чип `rule:X.Y` показывает текст пункта и ведёт в Положение.
- Карточка полей, предварительная проверка, распознанный текст, диалог с дополнительными вопросами, смена типа, экспорт JSON.
- Постоянная плашка: окончательное решение принимает сотрудник деканата (п. 1.3).

## Telegram-бот

`/start` → прислать фото или файл (подпись к фото — вопрос) → выбрать тип (или «определить автоматически») → карточка полей и предварительная проверка → любой текст = вопрос. Кнопки: проверить комплектность, карточка полей, снимок с разметкой, распознанный текст, Положение, новый документ. На вопрос о поле бот присылает фрагмент снимка с рамкой. Команды: `/new /check /fields /text /photo /type /rules /types /help`.
Бот не выполняет OCR и не формирует ответы — только вызывает API.

### Telegram Mini App

Веб-интерфейс открывается прямо внутри Telegram (кнопка «🌐 Открыть приложение», кнопка меню рядом с полем ввода,
команда `/app`, а после обработки документа — «Открыть документ в приложении» с переходом на его страницу).
Внутри Telegram сайт берёт тему клиента (светлая/тёмная), разворачивается на весь экран и прячет лишнюю шапку/футер.

Telegram принимает только публичный HTTPS-адрес, поэтому для локального запуска нужен туннель:

```bash
python scripts/tunnel_keeper.py --provider serveo --name dekanat-ci   # постоянный адрес https://dekanat-ci.serveousercontent.com
# без имени/регистрации: python scripts/tunnel_keeper.py  (localhost.run, случайный адрес, меняется при переподключении)
```

Постоянное имя serveo бесплатно: один раз зарегистрируйте SSH-ключ (`ssh-keygen -t ed25519`) на https://console.serveo.net/ssh/keys
(вход через Google/GitHub). На бесплатном тарифе serveo при первом открытии показывает страницу «Continue to Site».

Хранитель сам перезапускает туннель при обрыве, записывает актуальный адрес в `.env` (`WEBAPP_URL`) и в
`scripts/dev/webapp_url.txt`, обновляет кнопку меню бота; бот читает адрес при каждом построении клавиатуры,
поэтому перезапускать его не нужно. Без адреса кнопки Mini App просто не показываются, остальное работает.
Для постоянного домена подойдёт аккаунт localhost.run/ngrok или собственный HTTPS-хост — тогда задайте
`WEBAPP_URL` в `.env` вручную (`scripts/tunnel.ps1 -Cloudflare` — вариант с cloudflared, если VPN не блокирует DNS).

## Бонусы

- **Автоопределение типа** — по заголовку и набору меток полей; уверенность показывается в UI, при низкой — предлагается выбрать вручную. 30/30 на открытом наборе. Если тип выбран вручную неверно (справка об обучении загружена как заявление), сервис сообщает «выбран неправильный тип документа» и предлагает переключиться на распознанный тип одной кнопкой (веб и бот).
- **Плохие снимки** — `scripts/robustness_bench.py` аугментирует открытый набор (поворот на 90/180/270°, наклон 5/15/30°, перспектива, тень, блик, уменьшение ×0.5/×0.35, JPEG q30, шум, размытие, «фото телефоном») и считает те же метрики. Результаты — в `bench_report.json` (таблица ниже обновляется скриптом).
- **Новый тип без кода** — добавьте YAML в `config/doc_types/` (пример: `_example_new_type.yaml.disabled` → переименуйте в `transfer_application.yaml`), перезапустите сервис: тип появится в `/doc-types`, в веб-интерфейсе и в боте, поля извлекаются стандартными обработчиками (`text, person_name, date, int, enum, doc_number, group, signature, seal`).
- **Подсветка на снимке** — bbox каждого поля и отметки; оверлей в вебе, `crop.png` в боте, `annotated.png` для всего листа.

## Проверка обобщения (антипереобучение)

Словари в коде — только для полей с конечным набором значений (форма обучения, оценка) и для месяцев.

## Если что-то не работает

- **Бот отвечает «сервис недоступен», хотя бэкенд запущен.** На Windows с VPN-клиентом в системе часто задан прокси (`127.0.0.1:10809` и т.п.); клиент бота намеренно не использует системный прокси (`trust_env=False`), а `API_BASE_URL` должен указывать на `http://127.0.0.1:8000`, а не на `localhost` через прокси.
- **`pip install paddlepaddle` не находит версию.** Нужен Python 3.10–3.12 (`py -3.12 -m venv .venv`).
- **PaddleOCR падает с `ConvertPirAttribute2RuntimeAttribute`** — это oneDNN+PIR на Windows; ядро уже запускает детектор в режиме `run_mode=paddle`. Если ошибка осталась, обновите `paddlepaddle` до 3.x или задайте `DEKANAT_PADDLE_DET=PP-OCRv4_mobile_det`.
- **Tesseract не найден.** Укажите путь в `config/settings.yaml: ocr.tesseract_cmd` или переменной `TESSERACT_CMD`; `rus.traineddata` — в `models/tessdata` (скачивает `scripts/download_models.py`). Без Tesseract сервис работает на PaddleOCR.
- **Фронтенд не открывается на :8000.** Соберите его: `cd frontend && npm install && npm run build` (или используйте dev-сервер `npm run dev` на :5173).

## Ограничения
