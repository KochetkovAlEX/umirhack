# Презентация (≤10 слайдов) — план

1. **Проблема.** Деканат вручную читает фото справок, переносит данные и ищет пункты правил; студент ждёт и переспрашивает.
2. **Решение.** «Онлайн-деканат»: фото + вопрос → распознанный текст → карточка полей → предварительная проверка → ответ со ссылками `field:*` / `rule:X.Y`. Честный отказ, если ответа нет. Решение принимает сотрудник деканата (п. 1.3).
3. **Архитектура и стек.** Схема конвейера из README. PaddleOCR PP-OCRv5 (кириллица) + Tesseract 5 резерв; OpenCV; детерминированный QA без LLM; Django + DRF; React + Vite; aiogram. Всё локально, внешних API нет.
4. **OCR и плохие снимки.** Перспектива, наклон до 30°, тени, блики, апскейл; таблица robustness-бенчмарка.
5. **Поля, подпись, печать.** Конфиг типа (YAML) → метки/синонимы/пункты; нормализация дат «1 сентября 2026 года» → 2026-09-01; подпись/печать как графические элементы (п. 2.3), надпись «М.П.» — не печать.
6. **Положение → проверка → ответ.** Правила 6.1/6.2/6.3; `sources` для полного и неполного документа; интенты (решение, комплектность, поле, FAQ, «не установлено», отказ). Инвариант: sources пусты ⇔ answerable=false.
7. **Демо (скриншоты).** Три типа документов в вебе и боте: справка об обучении (не хватает даты выдачи, п. 3.1), заявление (полное, п. 4.1/4.2), справка о практике в Telegram (кроп поля). Случай без данных: «Какой размер стипендии?» → п. 6.3.
8. **Бонусы.** Автоопределение типа (30/30), новый тип через YAML без кода (демо `transfer_application.yaml`), подсветка поля на снимке (веб-оверлей + crop в боте), устойчивость к снимкам.
9. **Метрики.** Открытый набор PNG/PDF: 1.0 / 1.0 / 1.0 (`evaluate.py`); синтетический набор с новыми значениями; время ~4–6 с/документ на CPU; 110+ unit-тестов.
10. **Ограничения и развитие.** Одна страница, без рукописи; подлинность не проверяется (п. 2.6). Дальше: кабинет сотрудника, очередь обращений, больше типов документов через конфиги, дообучение детектора отметок.
